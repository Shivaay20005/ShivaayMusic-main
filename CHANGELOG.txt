#30 Update - 1.0.9 - 2026-10-31
-------------------
[Version]
- **Version 1.0.9 (Build 14)**: Bumped in `pubspec.yaml` (`1.0.9+14`), the startup build label in `lib/main.dart`, the Settings version fallback, `windows/runner/Runner.rc` (`1.0.9.14`), the Inno Setup `AppVersion`, and `LICENSE`.

[CI]
- **Windows Plugin Patch Is Idempotent**: The `Relocate symlink-unsafe plugin extraction targets` step failed when a cached pub cache already contained a patched `smtc_windows` CMakeLists. It now treats an existing `CMAKE_BINARY_DIR/plugin_native_bin` LibRoot as success and only patches (or errors) when neither form is present.
- **Windows Re-Publish Refreshes Assets**: Publishing the same version again deletes the old `Setup.exe`, `Portable.zip`, and checksum assets by name before uploading and retries each upload. This replaces `gh release upload --clobber`, which can fail with a stale-asset 404 and leave the previous build attached.
- **Same-Version Pushes Refresh the Release**: A push to `main` no longer skips publishing when the version tag already exists. The release assets (APKs, AAB, checksums, EXE, ZIP) are replaced in place and the tag is left untouched, so a fix can ship inside 1.0.9 without a version bump.

[Playback]
- **Spinner Stuck After the Song Started**: The play/pause button could keep showing the loading spinner for the whole track even though audio was playing. Three independent guards now clear it:
  - `MyAudioHandler` gained `_emitCurrentProcessingState()`, called from the `finally` block of `playByIndex` and `setSourceNPlay`. Previously `isSongLoading` was only translated into a processing state inside the playback-event listener; while the player stayed in `buffering` no new event arrived, so the published state remained `loading` forever. The error state published by `_reportPlaybackFailure` is preserved.
  - `PlayerController._listenForChangesInPosition()` now flips `PlayButtonState.loading` to `playing` as soon as the playback position advances. A moving position proves the stream is playing, regardless of the last buffering event.
  - **Android Media Notification Spinner**: The system notification showed a loading arc while the song was audible because `AudioService` renders `loading`/`buffering` as a spinner and just_audio can stay in `buffering` for a long time without emitting a new playback event. `MyAudioHandler` now tracks the position stream and publishes `ready` whenever the position changes while the notification still shows `loading`/`buffering`; the playback-event listener applies the same rule. A genuinely stalled buffer freezes the position, so the spinner still appears for real buffering.

[Auth]
- **Intermittent Login Screen After Clearing Recents**: A cold start could show `LoginScreen` even though the user was still signed in, because Firebase briefly reports no `currentUser` before it finishes restoring the persisted session, and the old 1.2 s fallback gave up too early and cleared the cached profile. `AuthService` now stores the last signed-in uid (`lastAuthUid`, with the old `userId` key as a fallback for upgrades), keeps the loading gate up, and confirms a `null` auth event by polling `FirebaseAuth.currentUser` for up to 8 s. Only a confirmed sign-out clears the cached profile; `signOut()` deletes the cached uid before signing out so the login screen appears immediately.

[Theming]
- **Contrast-Safe Colour Roles**: `ThemeController._withAccessibleComponents()` now derives `onSurface`, `onSurfaceVariant`, `onPrimary`, `onSecondary`, `onError`, and `onBackground` from the luminance of their own background (WCAG 0.179 threshold) instead of trusting `ColorScheme.fromSwatch`. This removes white-on-white controls in the light theme and white-on-light-accent controls in the dynamic theme.
- **Player Always Uses a Dark Theme**: The player screen now wraps its `Scaffold` in `Theme(data: ThemeController.playerTheme)`. The light theme used to render a white player with white text/icons; the dynamic theme could pair a light accent with white controls. The player now stays dark with a contrast-safe accent in every app theme, and the cached theme is invalidated whenever the theme mode or album-art palette changes.
- **Dynamic/Dark/Light Scheme Normalisation**: Dynamic theme now exposes `primary`/`secondary` = `primarySwatch[200]` with computed `on*` colours; the dark theme uses white accents with black `on*`; the light theme uses a black `secondary` with white `onSecondary`.
- **Progress Bars**: Buffered progress is now visible in every theme (dynamic/dark `white54`, light `black45`, player `white54`) instead of black-on-black or accent-on-accent.
- **Controls and Chips**: Play button icon/spinner takes an explicit `color` (`onSecondary` inside the accent circle, `onSurface` elsewhere); shuffle/loop/next disabled states use 45% `onSurface` instead of a 20% title colour; queue-loop chips in the player and home end-drawer use theme roles with readable label colours.
- **Switches and Toggles**: `CustSwitch` uses `ColorScheme` roles instead of guessing light mode from `primaryColor == Colors.white`; lyrics/video `ToggleSwitch`es use `primary`/`onPrimary` and a `onSurface`-blended inactive track instead of a light accent with hardcoded white labels.
- **Navigation**: Bottom navigation unselected icons are brighter (72% `onSurface`); the desktop sidebar uses `primary`/`onPrimary` so the selected pill and icon always contrast.
- **Snackbars and Dialogs**: Snackbar text follows `onSecondary`; the sleep-timer "Start" action, chat send buttons, profile avatar initial, up-next playing indicator, about-page icon, and listening-stats hero card no longer use hardcoded black/white that disappeared in one of the themes.
- **Shimmer Placeholders**: Loading placeholders use `onSurface` at 12% instead of white, so they are visible in the light theme too.
- **Container Roles**: `primaryContainer`, `secondaryContainer`, and `errorContainer` are now blends of their accent over the surface with computed `on*Container` colours, so text on the Music Room header, settings cards, and dialogs stays readable in every theme.
- **Desktop Search Bar**: The field and dropdown used `secondary` as their fill, which is white in the dark theme (white text/icons on white) and black in the light theme (black on black). Both now use an `onSurface` blend over the surface.
- **Up-Next Current Row**: The playing row no longer uses `secondary` as its `tileColor`; it uses a subtle primary tint, so the title, subtitle, and drag handle stay visible in the dark and light themes.

#29 Release - 1.0.8 - 2026-10-31
-------------------
[Release]
- **Version 1.0.8 (Build 13)**: Bumped everywhere the app exposes a version — `pubspec.yaml` (`1.0.8+13`), the startup build label in `lib/main.dart`, the Settings version fallback, `windows/runner/Runner.rc` (`1.0.8.13`), the Inno Setup `AppVersion`, and `LICENSE`.
- **Automatic Tagging**: A push to the default branch now creates the version tag from `pubspec.yaml` and publishes the GitHub Release without any manual step. A manual workflow run can still publish a selected branch through the `publish_release` checkbox.
- **All Android Formats**: Each release now ships the universal APK, per-ABI APKs (`arm64-v8a`, `armeabi-v7a`, `x86_64`), an Android App Bundle (AAB), and SHA-256 checksums.
- **Automatic Update Notification**: The release is mirrored to the legacy download repositories (`Shivaay20005/ShivaayMusic` and `Shivaay20005/ShivaayMusic-Windows-release`) so every already-installed copy receives the in-app “new version available” prompt. Mirroring is skipped with a warning when the `RELEASE_SYNC_TOKEN` secret is missing.
- **Windows Assets in the Same Release**: The Windows workflow now waits for the Android release job to create the tag, then attaches the installer and portable ZIP to the same release instead of only attaching on a tag push.
- **Release Flow Documented**: `RELEASE_FLOW.md` maps the complete pipeline — every workflow step, the exact build path and final file name of each artifact, which GitHub Release/artifact/legacy repository it is uploaded to, how the in-app update check finds it, and how to re-publish or force a mirror.

[CI]
- **Windows Build Failure (`smtc_windows`)**: The Windows job failed with `CMake Error: Problem with archive_write_header(): Cannot extract through symlink ...\.plugin_symlinks\smtc_windows`. That plugin always wipes and re-extracts its prebuilt DLLs at configure time, so pre-unpacking (the fix used for `audiotags`) cannot help. A new `Relocate symlink-unsafe plugin extraction targets` step rewrites the plugin's `LibRoot` to `${CMAKE_BINARY_DIR}/plugin_native_bin/${LibraryVersion}`, so the archive is only *read* through the symlink and unpacked into the real build tree.
- **Mirror-Only Workflow**: New `.github/workflows/mirror_release.yml` re-publishes an existing release into `Shivaay20005/ShivaayMusic` (Android) and `Shivaay20005/ShivaayMusic-Windows-release` (Windows) without rebuilding. It splits assets by platform, never creates an empty release for a platform whose build failed, and moves the *Latest* badge with `gh release edit --latest`. Useful whenever a build fails after the other platform already published.
- **Mirror Re-publish Robustness**: `gh release upload --clobber` can fail with `HTTP 404` on a stale asset id when a release is published more than once, and deleting the release to work around it left installed copies with a dead download link. All mirror steps now create the release once (if missing), delete matching assets by name through the API, upload each file with up to three retries, and move the *Latest* badge afterwards.

[Critical Fixes]
- **Windows/Linux Audio Backend**: `JustAudioMediaKit.ensureInitialized()` is now called in `main()` before any `AudioPlayer` is created. Without it just_audio kept the default mobile-only platform implementation, so desktop playback never loaded any audio. `media_kit`, `media_kit_libs_linux`, and `media_kit_libs_windows_audio` are now declared directly in `pubspec.yaml` instead of relying on a stale transitive resolve.
- **Startup Deadlock (Restore Session)**: `MyAudioHandler._init()` no longer calls `restoreSession()`. That method uses `checkNGetUrl()`, which awaits `_initCompleter`, while the completer was only completed after `_init()` returned, so users with a saved session waited for the full 30-second startup timeout. Session restore stays with `PlayerController._restorePrevSession()`.
- **Session Restore Robustness**: `_restorePrevSession()` is wrapped in a guarded block, skips corrupt saved queue entries instead of aborting, clamps the saved index to the restored queue length, and always closes the Hive box. Session serialization also tolerates media items without `extras`.
- **403 / Expired Stream Recovery**: Playback errors now recover for `PlayerException` too (previously only the generic branch retried), fetch a fresh media URL once per song, and resume near the previous position. A second failure shows a Retry snackbar instead of leaving the player stuck.
- **Stuck Loading State**: `playByIndex` and `setSourceNPlay` are wrapped in `try/catch/finally`, so `isSongLoading` is always reset and a failed fetch can no longer leave the player permanently loading.
- **Missing Cached Song Files**: `checkNGetUrl()` now verifies that `cachedSongs/<id>.mp3` still exists before returning a `file://` URL. Android clearing the temporary cache directory previously produced unplayable cached entries; the stale Hive entry is removed and the song falls back to online streaming.
- **Null Safety in Stream Data**: `SMStreamingData.fromJson()` rejects playable responses without audio formats, cached-URL expiry checks no longer dereference `lowQualityAudio` blindly, and the quality getters in `StreamProvider` return `null` instead of throwing on empty format lists.
- **Cache Directory Init Race**: `_createCacheDir()` is now awaited inside `_init()` instead of running detached from the constructor. `_cacheDir` is `late final` and is used by `checkNGetUrl()`/`_createAudioSource()`, so the previous ordering could throw `LateInitializationError` on a fast start.
- **Downloaded Song Cache Fallback**: The fallback for a missing `SongDownloads` entry is now a typed map (`<String, dynamic>{}`) instead of the inferred `Map<dynamic, dynamic>` from a bare `{}`, and `Audio.fromJson()` tolerates old/incomplete cache entries (missing codec, itag, size, or URL) instead of throwing.
- **Unplayable Cached Entries**: A cached stream entry whose audio URLs are both empty is now reported as a playback error instead of being handed to just_audio as an empty URL.

[Playback]
- **End-of-Track Double Skip**: Added an `_isAdvancing` guard around the position-stream trigger. The stream emits several times while the position sits at the end, which previously called `skipToNext()` multiple times and skipped songs.
- **Faster Song Start**: Smart prefetch is enabled by default and now warms the next track's URL as soon as a song starts and again when the queue is replaced, instead of waiting for the last 30 seconds. The prefetch window was widened to 45s / 75%.
- **Prefetch Throttling + Shuffle Safety**: Each prefetch attempt is recorded for the current track, so the position stream can no longer re-run a failing extraction several times per second (which hammered YouTube). Prefetching uses a non-mutating `_peekNextSongIndex()` so it no longer consumes the shuffle cursor.
- **Queue Race**: `pushSongToQueue` tags its watch-playlist request with an incrementing id, and stale responses are ignored. `updateQueue()` now keeps `currentIndex` pointing at the actually playing item when the queue is replaced asynchronously.
- **Index Guards**: `playByIndex`, `skipToNext`, `skipToPrevious`, and the shuffle helpers validate indices (including `-1`/`null`) instead of crashing or playing the wrong item. “Play next” also clamps its shuffle-list insertion point, and `addQueueItems()` clamps the shuffle cursor before `sublist()`/`replaceRange()`, so an empty or desynced shuffle queue cannot throw a `RangeError`.
- **Isolate Helper**: `getStreamInfo()` only strips the `MPED` prefix when the id is long enough, avoiding a `RangeError` for short ids.

[Windows]
- **SMTC Service Hardening**: Windows media controls enable SMTC before publishing status, guard every SMTC call, only set the end time when a duration is known, and cancel all stream subscriptions on close.

[Update Checker]
- **Correct Version Comparison**: `newVersionCheck()` now compares dotted versions part-by-part, so `1.0.10` is correctly newer than `1.0.9`, short tags such as `1.0` no longer crash, and a `+build` suffix is ignored.
- **Highest Tag Wins**: Every tag is scanned and the highest semantic version is used instead of trusting `tags[0]`, whose ordering is not guaranteed by the GitHub API.
- **Releases API First**: The check reads `releases/latest` first (the actually published build) and falls back to the tags list, with GitHub API headers and a 10-second timeout so a slow network cannot block startup.
- **Build Repository Fallback**: The check now also looks at the build repository, so a new release is detected even if the legacy mirror step has not run yet. Windows builds additionally check the Windows download repository.
- **Reliable Startup Dialog**: The update dialog now waits for a usable navigator instead of dereferencing a null context, so the notification is actually shown on cold start.

[Reliability]
- **Global Error Handling**: `FlutterError.onError` and `PlatformDispatcher.instance.onError` now log uncaught framework/async errors instead of dropping them silently.
- **CI Hardening**: `github.ref_name`, `github.ref_type`, and `github.event_name` are passed through `env:` variables instead of being interpolated into the shell script, closing a script-injection vector.
- **Windows Checksums**: The Windows checksum list is generated from a file snapshot taken before the checksum file is written, so the checksum file can no longer include a hash of itself.

[Dependencies]
- **Pinned Extraction Library**: `youtube_explode_dart` is pinned to `3.1.0` (the current latest) because minor releases change extraction behaviour and have broken playback before.
- **Regenerate Lockfile**: Run `flutter pub get` after pulling these changes so `pubspec.lock` picks up the newly declared media_kit packages.

#27 Update - 1.0.7 - 2026-09-09
-------------------
[Fixes]
- **Listening Stats**: Listening time is now measured from real playback position updates and saved while a song is actually playing. Fixed the first daily entry being lost because a newly-created Hive object was saved before it was attached to its box.
- **AudioHandler Builder Registration (Critical)**: Fixed the remaining `"AudioHandler" not found` initialization window. `AudioService.init` executes its builder before returning, so moving service calls alone was insufficient; the concrete handler is now registered inside the builder at the exact moment it is created, with duplicate-safe registration after initialization.
- **AudioHandler Startup Order**: AudioService also initializes before any dependent app controller; only the dependency-safe Settings controller is pre-registered for playback restoration.
- **Build Identification**: Startup and failure screens now show the exact build number and failing startup stage, preventing an older extracted APK from being mistaken for the latest build.
- **Lazy Booster Dependency**: Audio Booster now resolves AudioHandler only when an effect is used instead of during controller construction, removing another startup-order race.
- **Native Splash Freeze Hotfix**: Flutter renders a branded startup screen before Firebase, local storage, and audio plugins initialize. Every startup stage has a timeout, and fatal plugin failures display a readable diagnostic instead of a black screen.
- **Listening Startup Isolation**: Listening analytics initialize safely in the background and can never block the app on an existing/legacy Hive box.
- **Safe Stats Migration**: Song display metadata now uses its own schema-free Hive box instead of changing the persisted daily-stat adapter. Existing installs, including data written by build 7, remain readable without clearing app data.
- **Stats Startup Reliability**: The stats page waits for analytics initialization while the rest of the app starts immediately.
- **Visible Short Listens**: Listening time and top-track durations now show seconds for plays under one minute instead of appearing stuck at `0 min`.
- **Playback Restoration (Critical)**: Fixed songs not playing at all (endless loading, then YouTube's "you may need to refresh the page" style error). Root cause: the bundled YouTube stream-extraction package (youtube_explode_dart 2.3.7, pinned to a git fork that has since been deleted) used 2024-era extraction clients (IOS 19.29.1 / TVHTML5). Since mid-2026 YouTube enforces PO-Tokens / JS signature challenges on those clients and answers their media URLs with HTTP 403 (upstream issues #386, #389, #390).
- **Dependency**: Moved `youtube_explode_dart` from the deleted git fork to the official pub.dev release (^3.1.0). This also fixes fresh builds failing at `flutter pub get` with "Repository not found".
- **Stream Client**: `StreamProvider.fetch` now tries a client fallback chain — a built-in VISIONOS (Apple Vision Pro) client payload (the same client yt-dlp uses; currently served without PO-Token), then `androidSdkless`, then `tv`. If YouTube rotates clients again, only the payload in `lib/services/stream_service.dart` needs updating.
- **API Migration**: Migrated to youtube_explode_dart v3 (no more per-stream `duration`/`loudnessDb`/exception `.reason` getters); error snackbar now shows the short human-readable reason from YouTube.
- **Loudness Normalization**: Skipped when loudness data is unavailable (v3 reports 0), preventing every song from being attenuated to ~56% volume.
- **Resource**: The `YoutubeExplode` client used for stream fetching is now properly closed after use.

[UI & Experience]
- **Modern Listening Dashboard**: Rebuilt Listening Stats with a polished responsive layout, 7/30-day switcher, activity graph, listening-time hero, active-day and daily-average cards, improved empty state, and ranked top-track cards.
- **Track Details in Stats**: New listens now retain each track's title, artist, and artwork locally and in the user's Firestore stats, replacing raw song IDs with a useful visual listening history.
- **First-Visit Home Message**: “Your soundtrack is ready” is shown only on the user's first Home visit. The seen state is stored locally, so the introductory card stays out of the way afterwards.
- **Version Consistency**: The public app version remains 1.0.7 everywhere; the Android/iOS build number is now 12 so the AudioService builder-registration fix installs over previous builds.

[CI/CD]
- **Automatic Android Builds**: Every pushed branch and pull request now runs dependency installation, source analysis, and both universal and per-architecture release APK builds. Versioned APKs and SHA-256 checksums are retained as GitHub Actions artifacts for 30 days.
- **Tagged GitHub Releases**: A successful push to the repository's default branch automatically creates the version tag from `pubspec.yaml` (for example `v1.0.7`) and publishes all APKs plus checksums to GitHub Releases. A workflow-dispatch checkbox can explicitly publish a selected non-default branch.
- **Safe Version Guard**: If the version tag already exists, CI keeps the new build artifact but does not overwrite or move the existing release tag; the app version must be bumped before another release.

[Notes]
- After pulling this update run `flutter pub get` (pubspec.lock entry for the old fork was removed; it will be re-pinned automatically), then rebuild and reinstall the app. The previously installed app cannot be fixed in place — this fix ships with the new build.
